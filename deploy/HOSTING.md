# خرید دامنه و میزبانی نسخه آزمایشی

تاریخ بررسی: ۲۰۲۶/۰۹/۰۵. هیچ خرید، ثبت دامنه یا قراردادی از طرف پروژه انجام نشده است. منابع زیر پیشنهاد اولیه مهندسی برای استقرار و آزمایش‌اند، نه ظرفیت تضمین‌شده تعداد مشتری یا کاربر هم‌زمان.

## پیشنهاد خرید

اگر نام محصول قطعی است، دامنه را می‌توان اکنون با مالکیت و ایمیل خودتان ثبت کرد؛ برای ادامه کدنویسی لازم نیست. یک دامنه و زیردامنه‌های `app` و `staging` کافی‌اند و API می‌تواند زیر همان مبدأ پنل باشد. برای بازار داخلی `.ir` قابل بررسی است؛ ثبت `.com` هم برای نام تجاری اختیاری است. پسوند دامنه تضمین کارکرد در شبکه داخلی نیست. DNS و مسیر سرویس باید جداگانه بررسی شوند.

برای میزبانی، پیشنهاد اول **VPS ایران با مدیریت سرویس توسط میزبان و منابع قابل ارتقا** است. قبل از خرید، تعهد مدیریت سیستم‌عامل، Node، PHP، پروکسی، امنیت و بکاپ را صریح بگیرید؛ «پشتیبانی سرور» لزوماً مدیریت برنامه نیست. برای شروع قرارداد ماهانه/دوره آزمایشی مناسب‌تر از تعهد بلندمدت است.

| مورد | آزمایش کم‌ترافیک | پیشنهاد برای شروع پایلوت محدود |
| --- | --- | --- |
| CPU | ۲ vCPU | ۴ vCPU |
| RAM | ۴ گیگابایت | ۸ گیگابایت |
| دیسک | ۴۰ گیگابایت SSD/NVMe | ۸۰ گیگابایت NVMe |
| محل | ایران | ایران، با امکان ارتقای منابع |
| بکاپ | جدا از فضای اصلی | روزانه خارج از سرور + امکان بازیابی آزمایشی |

این برآورد برای موتور دانش فعلی است، نه اجرای مدل زبانی بزرگ روی همین سرور. اگر پنل مدیریتی سنگین، build روی سرور و staging روی همان ماشین باشند، منابع بیشتری مصرف می‌شود. حجم فایل‌های مشتری و مدت نگهداری تعیین‌کننده نیاز دیسک است؛ یک دیسک ۸۰ گیگابایتی وعده فضای نامحدود به مشتری نمی‌دهد. ترافیک خروجی، هزینه اضافه‌مصرف و امکان snapshot را هم استعلام کنید.

## درباره cPanel

cPanel می‌تواند Node را از طریق Application Manager/Passenger ارائه کند، اما فعال‌سازی این قابلیت در اختیار میزبان است؛ وجود آیکون cPanel تضمین اجرای Next.js نیست. [مستند رسمی Application Manager](https://docs.cpanel.net/cpanel/software/application-manager/)

یک ریسک مهم برای هدف میزبانی ایران: در صفحه رسمی cPanel، فروش محصولات به ایران ممنوع اعلام شده و احتمال لغو لایسنس واسطه‌ای نیز ذکر شده است. بنابراین cPanel را برای این استقرار پیش‌فرض مطمئن فرض نکنید؛ وضعیت مجاز لایسنس و پشتیبانی باید روشن باشد و نباید روی نسخه کرک‌شده یا راه دورزدن محدودیت تکیه کرد. VPS مدیریت‌شده با پنل قابل‌ارائه رسمی یا مدیریت بدون cPanel را هم بررسی کنید. [توضیح رسمی cPanel](https://www.cpanel.net/us-embargo-details/)

هاست اشتراکی فقط وقتی گزینه آزمایشی است که فروشنده اجرای همین ترکیب Next/PHP و SSE را عملاً تأیید کند. در کد فعلی هر اتصال SSE درخواست PHP را تا حدود ۲۵ ثانیه باز نگه می‌دارد؛ تعداد اتصال هم‌زمان، سقف PHP workers/EP/NPROC و buffering مهم‌تر از برچسب «هاست نامحدود» هستند. این عدد مدت stream است، نه ظرفیت تعداد کاربران.

## نرم‌افزارها و امکانات موردنیاز

- Node.js نسخه ۲۴ LTS ترجیحاً؛ ۲۲ LTS با تست سازگاری قابل بررسی است. حداقل قدیمی ثبت‌شده در package.json معیار انتخاب نسخه جدید سرور نیست. [چرخه نسخه‌های رسمی Node](https://nodejs.org/en/about/previous-releases)
- PHP 8.3 یا 8.4 با آخرین patch و آزمون سازگاری پروژه؛ تست فعلی محلی روی 8.2 است، پس نسخه مقصد هنوز تأیید نشده. افزونه‌های `pdo_mysql`, `mbstring`, `curl`, `openssl`, `fileinfo`, `dom`, `sodium` و OPcache فراهم باشند. [وضعیت پشتیبانی PHP](https://www.php.net/supported-versions.php)
- MariaDB 10.11 یا 11.4 با utf8mb4 و InnoDB؛ نصب schema و migration باید روی همان نسخه آزموده شود. نسخه قدیمی محلی 10.4 را معیار خرید قرار ندهید. [سیاست نگهداری MariaDB](https://mariadb.org/about/)
- SSH یا Terminal برای npm/PHP CLI، امکان build یا بارگذاری build سازگار با لینوکس و کنترل restart برنامه.
- فرآیند دائمی Next در حالت production و امکان نگاشت `/backend/api` به PHP زیر همان HTTPS origin.
- پشتیبانی عملی `text/event-stream`، خروجی بدون buffering، timeout مناسب و عدم cache روی API و stream؛ صرف پشتیبانی WebSocket کافی نیست چون پروژه فعلاً SSE دارد.
- Cron با فاصله یک دقیقه، اجرای PHP CLI، مدیریت لاگ و جلوگیری از اجرای هم‌پوشان workerها.
- TLS و تمدید مدیریت‌شده گواهی، زیردامنه staging، آپلود پایدار غیرقابل‌اجرا و دسترسی به لاگ‌های برنامه/وب‌سرور.
- بکاپ خارج از ماشین اصلی، مدت نگهداری و هزینه restore مشخص؛ snapshot ماشین جایگزین تست بازیابی دیتابیس و فایل‌ها نیست.

## گزینه برای استعلام، نه تأیید خرید

[سرور ایران پارس‌پک](https://parspack.com/vps/iran) یک گزینه برای استعلام زیرساخت و ارتقای منابع است؛ صفحه فروش به‌تنهایی مدیریت کامل این برنامه یا سازگاری SSE را ثابت نمی‌کند. قیمت جاری، نوع مدیریت و پاسخ به متن زیر باید پیش از پرداخت تأیید شوند. هنوز این پروژه روی این سرویس آزمایش نشده و توصیه قطعی فروشنده صادر نشده است.

## متن آماده برای فروشنده

> برای یک SaaS چت با Next.js 16.3.3، PHP و MariaDB به میزبانی ایران نیاز دارم. منابع مدنظر ۴ vCPU، رم ۸ گیگ و NVMe حدود ۸۰ گیگ است. آیا Node 24 LTS و اجرای production Next، PHP 8.3/8.4 با افزونه‌های PDO MySQL، mbstring، curl، openssl، fileinfo، dom و sodium، و MariaDB 10.11/11.4 را پشتیبانی می‌کنید؟ API PHP باید زیر همان دامنه پنل در /backend/api اجرا شود. اتصال SSE در PHP حدود ۲۵ ثانیه باز می‌ماند و نباید buffer/cache شود؛ سقف PHP workers و اتصال هم‌زمان، EP/NPROC و timeout دقیقاً چقدر است؟ Cron هر دقیقه، SSH، restart برنامه، HTTPS، staging، بکاپ خارج از سرور و restore دارید؟ مدیریت سرویس‌ها و رفع خرابی چه مواردی را پوشش می‌دهد؟ محل واقعی IP، دسترسی DNS و سرویس در شبکه داخلی، اعتبار مجاز پنل مدیریتی، هزینه مدیریت/لایسنس/بکاپ/ترافیک و امکان تست پیش از تعهد بلندمدت را نیز اعلام کنید.

پاسخ و لینک پلن را قبل از خرید بررسی کنیم. رمز پنل یا کلید خصوصی را در مکاتبه استعلام نفرستید.
